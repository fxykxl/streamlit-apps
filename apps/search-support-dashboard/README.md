# Search & Support Effectiveness Dashboard

An executive-level Streamlit dashboard that answers one question: **are people (and support agents) finding what they're looking for, and what does it cost when they don't?**

> **All data in this repository is synthetic.** "Quillstone Software" is a fictional company; agents, cases, queries and articles are generated by `generate_data.py`. The structure mirrors analysis I do on real search and support data, but no client data is used here.

## What's inside

| Page | Question it answers |
|---|---|
| **Executive overview** | Headline KPIs with trend and period-over-period deltas, success by product area, auto-generated insights, biggest gaps, and what a failed search costs in case outcomes |
| **Search performance** | Funnel, time to first click, latency (p50/p95) vs. incidents, click position, best hours/days, reformulation effort, channel comparison |
| **Content gaps** | Unresolved-demand treemap, diagnosis per topic (*no article · vocabulary mismatch · weak content · recovered*), fix-first list with trends, new-feature docs lag, top zero-result queries, articles that get clicked but don't resolve |
| **Agent effectiveness** | Success and speed by agent and team, ramp-up curve, coaching shortlist, searches per case, and the link between finding an answer and resolution time / escalation / CSAT |
| **Query explorer** | Drill-through: top queries, filterable search log with CSV export, and session replay |

Global filters (sidebar): period, who is searching (agents / customers), product area. Charts are Plotly with a custom dark theme; release, incident and content-launch events are annotated on time series.

## Metric definitions

| Metric | Definition |
|---|---|
| Search success rate | Share of search *sessions* that ended with a resolving click |
| Click-through rate | Share of *searches* with at least one click |
| Zero-result rate | Share of searches returning nothing |
| Time to first click | Median seconds from query to first click |
| Self-service resolution | Share of customer sessions resolved without opening a case |
| Reformulation rate | Share of searches followed by another search in the same session |
| Diagnosis (per topic) | Based on the most recent 28 days: no article → *No article*; zero-results ≥ 15 % → *Vocabulary mismatch*; clicked but success 10 pts below average → *Weak content*; failing earlier but healthy now → *Recovered* |

## Run locally

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1          # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

Tip: keep the folder (and the virtual environment) **outside OneDrive/Dropbox**; synced folders cause permission errors on Windows.

The `data/` folder is committed so the app starts instantly. To regenerate (deterministic for a given seed):

```bash
python generate_data.py --seed 42            # add --scale 0.5 for a lighter dataset
```

If `data/` is missing, the app generates the data in memory on first load.

## Data model (synthetic, 6 months: 2026-05-01 to 2026-10-31)

| Table | Rows | Notes |
|---|---|---|
| `searches` | ~100k | one row per query: results, click, rank, time to click, latency, outcome |
| `sessions` | ~68k | a person searching until they resolve it or give up (agents and customers) |
| `cases` | ~18k | support cases: priority, resolution time, escalation, CSAT |
| `articles` | ~180 | knowledge-base articles with publish/update dates and helpful votes |
| `agents` | 40 | four teams, tenure |
| `events` | 4 | release / incident / content annotations used on charts |

### Planted patterns (so there is a real story to find)

1. **Search regression**, 21–27 Jul: index migration → more zero results, lower CTR, slower clicks, latency spike.
2. **Launch without docs**: Workflow & Automation launches 17 Aug, docs go live 8 Sep. Three weeks of unanswerable demand, then recovery.
3. **Persistent gaps**: Integrations has several topics with no article (Salesforce mapping, Slack, Zapier, Teams); SCIM, PO invoicing, field-level permissions, HIPAA and embeds too.
4. **Vocabulary mismatch**: people search "app crashing" / "locked out" / "import stuck"; the articles are worded differently.
5. **Weak and stale content**: API & Webhooks is stale; a few articles are clicked often but rarely resolve.
6. **Mobile incident**, 9–12 Jun: spike of crash searches.
7. **Agent spread**: a handful of very strong agents, eight brand-new agents, a visible ramp-up curve.
8. **Search matters**: cases where the agent found an answer resolve faster, escalate less and score higher CSAT.
9. **Seasonality**: weekday/weekend, hour of day, month-end billing spike, holidays, gentle growth.

## Project layout

```
app.py                    entry point: theme, filters, navigation
generate_data.py          seeded synthetic data generator
dashboard/
  data.py                 loading, filters, shared context
  metrics.py              pure-pandas metric definitions (no UI imports)
  charts.py               Plotly figure builders
  theme.py                palette, CSS, KPI/insight cards
  components.py           KPI row helper
  views/                  one module per page
data/                     generated CSVs (gzip)
.streamlit/config.toml    dark theme
```

## Using real data

Everything downstream of `dashboard/data.py::_prepare` expects the tables above. To point the dashboard at real exports (search-analytics events, a support-desk export, a content inventory), map them to those columns; the metric, chart and page code stays unchanged.
